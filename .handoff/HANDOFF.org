* Just shipped: e35aefe — the hub status rewrite fix

Bug: the =substitute*= for =hub status= in =sane-packages/cline.scm= never
applied, so CI's smoke test kept upstream's TCP probe and failed.

Root cause, now documented in the file: =substitute*= is strictly
line-based.  =guix/build/utils.scm='s =substitute= loops on
=read-line in 'concat= and applies every pattern to that single line, so a
PATTERN containing a newline can NEVER match — however its spans are
written.  The old pattern spanned two source lines and was therefore dead
code.  Replacement strings, in contrast, may contain any number of
newlines.

Fix: three single-line anchors.

  1. =const status = JSON\.parse\(= opens the promise and emits the entire
     poll-the-discovery-file body as one multi-line replacement string.
     Poll reads =readFileSync(smokeEnv.CLINE_HUB_DISCOVERY_PATH)= every 200 ms
     for up to 30 s and resolves when =authToken= appears — the daemon writes
     that record right after a successful bind (hub server.ts
     =writeHubDiscovery=), so its presence proves bound state, which is the
     same signal =hub start= waits for minus the socket.
  2. the =await $`...hub status`.env(smokeEnv).text(),' line is emptied.
  3. the closing =) as { running?: boolean; coreVersion?: string };-> becomes
     =});' so the promise terminates and the following
     =if (!status.running || !status.coreVersion)= consumes it unchanged.

How it was verified (repeat this pattern, it works): the forms were lifted
verbatim out of cline.scm by a paren-matching extractor — see
/tmp/extract-buildts-forms.py from that session — and applied to a pristine
copy of =apps/cli/script/build.ts= at tag =cli-v3.0.70= (/tmp/build.ts.orig
is the saved copy; it may still exist).  Then asserted: promise opens, no
leftover =hub status`= exec, no leftover type assertion, =poll()= present,
consumer clause intact, =readFileSync= used, the loader rewrite and the
0.0.0.0 rewrite from the other forms in the same file still applied, braces
balanced 13/13 in the block and 128/128 file-wide.  =guix style -f= was
idempotent and =guix build -L . --dry-run cline-baseline= exited 0.

Watch for in the next CI run: a =channel: unbound variable= / =guix channels=
warning appears on =guix build --dry-run= for every package in this checkout.
It is pre-existing and harmless (same message on =dsh=), not caused by this
change.

* Open risks — check these first

** 1. Placeholder output hash blocks the cline-baseline network build

=%cline-baseline-source= in =sane-packages/cline.scm= still carries
=sha256 (base32 "0000...0000")=.  =cline-baseline-build= is a custom origin
METHOD that forwards =#:hash= / =#:hash-algo= to =gexp->derivation=, which is
what makes it a fixed-output derivation — and a fixed-output derivation
fails the build on hash mismatch.  So the moment CI actually runs the
network build it will fail until the real hash is substituted in.

Next action: read the hash out of the failed CI run's log (or recompute the
build locally IF AND ONLY IF it is a =*-bin= style repack, which it is not —
so: CI log only), then edit =%cline-baseline-source= to the real value.

** 2. Unverified daemon env var name

The generated TS spawns the daemon with =CLINE_RUN_AS_HUB_DAEMON= in the
environment, but the real constant appears to be =CLINE_RUN_AS_HUB_DAEMON_ENV=,
re-exported from =@cline/shared= → =./runtime/hub-daemon-env=, whose source
was never saved locally, so its literal string value was never confirmed.
If it differs, =isHubDaemonProcess()= (daemon.ts:451 and :496) returns false
and the spawned process runs the normal interactive CLI personality instead
of the daemon one.

Next action: find the literal string value of =CLINE_RUN_AS_HUB_DAEMON_ENV= in
the installed package's compiled output under =sdk/packages/shared/= (a
=grep -r= inside the installed store path, bounded, is fine — that is a local
read, not a build), and correct the env var name in the generated TS if it
differs.
